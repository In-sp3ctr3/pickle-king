## Design and acceptance

The user action is a maintainer starting or resuming a Linear ticket, selecting a checkout, running verification, reviewing evidence, then deciding whether a PR or release is ready. Linear owns ticket state; Git owns source and branch truth; GitHub owns PR/CI truth. The ignored `STATE.md` is a cache. Missing or contradictory facts stop a dependent claim rather than becoming a pass.

| Acceptance                                | Observable check                                                                                                                                                          |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Existing native coverage remains          | Default `scripts/verify` runs Vinext check, formatting, and `npm run check`; CI uses the same wrapper.                                                                    |
| Full coverage preserves CI's share gate   | Full mode starts the production server on a validated free port, runs `test:share-visual`, and tests built PWA/rendered HTML artifacts.                                   |
| Invalid/ambiguous modes fail              | Wrapper test checks invalid and conflicting arguments, native failure propagation, and changed-mode fallback.                                                             |
| Continuation survives missing cache       | `LIFECYCLE.md` directs reconstruction from Linear, Git, PR and relevant docs; `.work/active` is ignored.                                                                  |
| Hygiene is non-destructive                | Adopted command reports Git/PR residue and refuses unknown overlap; no cleanup command is embedded.                                                                       |
| Provenance answers staleness              | Manifest pins OS SHA and source paths; status command compares pinned and requested OS trees without replacing local files. Test changed source and local override paths. |
| Architecture and product remain untouched | Diff review confirms no app, feature spec, dependency, or branch-only architecture file changes.                                                                          |

Risk is medium: false-green verification or incorrect source provenance could weaken future delivery. Positive path: current Linear scope → Git/PR inventory → validated command modes → native checks → exact-head CI/review → bounded release decision. Negative paths: stale checkpoint, unknown overlap, missing command, failed native check, unknown deployment target, or changed PR head leave the affected gate incomplete. This change does not add product data flow, auth, migration, flag, telemetry, or deployment operation. Rollback is reversal of only this harness diff.
