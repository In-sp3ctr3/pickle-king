## Design contract

The maintainer action is: generate a normal Pickle King ticket prompt, execute the ticket under the existing lifecycle, assess Engineering OS feedback at checkpoint or close, write the assessment to the OS-owned private run ledger, and retain only references and unresolved signals in the ignored checkpoint cache. Linear remains ticket authority, Git/GitHub remain source and PR authority, and `codex-os` remains the policy and ledger-schema owner.

Positive journey:

`ticket ID + repository ID -> local prompt validation -> generated prompt with mandatory footer -> ticket execution -> explicit none or structured observations -> shared OS ledger -> checkpoint references -> Steward stocktake`

Material negative journeys:

- Invalid prompt identifiers fail before rendering.
- Missing or malformed feedback remains unassessed/gapped; it never becomes implicit `none`.
- A later `none` assessment does not close an earlier unresolved observation.
- An unavailable shared ledger is a visible checkpoint gap; Pickle King does not create a fallback incident database.
- Malformed GitHub actor evidence fails closed; human and lookalike logins are not Dependabot.
- A changed OS SHA outside the shared harness path reports upstream movement without claiming a relevant upgrade. Shared harness changes, local drift, and intentional overrides remain separate states.

The executable integration boundary is `scripts/eng-os-feedback --os-repo PATH --ledger PATH --registry PATH`. All arguments are mandatory. The adapter requires an existing regular private ledger, a verified Steward registry, an OS checkout at the manifest's exact adopted commit, and matching pinned blobs for the shared feedback CLI, feedback module, ledger module, and stocktake CLI. It authenticates the repository, ticket, run, and reporter against the registry before mutation, requires a controlled JSON assessment with `assessment_id`, `repo`, `ticket`, `run_id`, `reporter_ref`, and timezone-aware `at`, then delegates schema and atomic persistence to the shared CLI. The assessment ID is the checkpoint reference retained by Pickle King. Missing checkout, mismatched runtime, absent ledger/registry, unauthorized identity, malformed input, or shared-command failure exits nonzero and leaves feedback explicitly gapped. There is no default ledger path and no fallback local database.

There is no product authorization, validation, persistence, API, dependency, migration, feature-flag, deployment, or UX change. Feedback records are bounded references and controlled classifications; secrets, transcripts, and local paths remain prohibited by the shared OS mechanism. Rollback is reversal of this harness-only diff.
